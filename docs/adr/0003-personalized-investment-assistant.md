# ADR-0003: 个性化投资助手设计

## 状态
已接受；正式实现与验收见 `docs/personalized-investment-assistant.md`，档案和纠错由 ADR-0007 补充。

## 背景
平台核心差异化能力是个性化投资助手：每个投资者的交易策略不同（买卖点、复盘方法、牛熊市下的应对方式等），系统需要结合"用户自己的策略知识 + 实时行情 + 公共理财知识库"生成个性化提示。

## 决策
### 策略的来源：文档导入优先
用户的交易策略**不通过结构化表单录入**，而是通过**导入文档**形成：
- 书籍 PDF（如《股票大作手回忆录》《江恩理论》等）
- 他人或自己的炒股心得（Markdown/PDF/文字）
- 后续可手动文字补充、优化策略内容

这与现有 RAG 管道天然契合：文档导入 → 解析 → 切分 → BGE-M3 向量化 → Milvus 入库。策略内容中自然包含牛熊市应对方式（作为文档内容的一部分，不单独建功能模块）。

### 三层知识隔离
在 Milvus 中通过 `owner_id` + `doc_type` 字段区分三类文档：
| doc_type | 含义 | 可见范围 |
|----------|------|----------|
| `personal` | 用户自己的策略文档、心得 | 仅该用户 |
| `knowledge` | 公共投资理财书籍（经典著作） | 所有用户 |
| `review` | 用户的复盘记录（自然语言原文 + 提取摘要） | 仅该用户 |

### 双模式提示
1. **每日投资摘要（主动生成）**：收盘后抓取当日行情，结合用户策略生成摘要并存储，前端拉取展示，不发送外部消息。
2. **按需查询（被动）**：用户主动提问，LangGraph 从 `personal`、`knowledge`、`review` 三路检索并 RRF 融合；行情作为单独的结构化上下文补充后生成回答。

### 复盘记录：自然语言输入
- 用户以**自然语言**（类似写交易日记）描述交易，例如：“今天 12.5 追高买了 XX，被套后反思没等支撑位就冲进去，心态很急。”
- LLM 从自然语言中**自动抽取**结构化字段：股票代码、买卖价格、买卖原因、反思教训、情绪标签；抽取结果与原文一并存入 MongoDB 集合 `trade_reviews`。
- **解析容错**：LLM 输出不一定是纯 JSON，需做“正则提取 JSON 子串 + 失败降级保留原文”的容错逻辑；抽取失败不阻塞复盘保存，原文始终保留供人工校验。
- 同时将该复盘内容（原文 + 摘要）向量化存入 Milvus（`doc_type=review`），使复盘教训可被后续查询召回（如“我上次追高被套的教训”）。
- 自动获取持仓功能**暂不实现**（依赖券商接口，难度大），预留扩展。

### 原型验证结论（原型 2：LLM 自然语言复盘字段抽取）
- 本地模型 group/group 的 6 个样本均能解析为 JSON，仅验证了格式。
- 尚未证明语义正确；正式实现需区分交易计划与已执行交易、识别名称与代码冲突，缺失代码保持为空。
- 方向验证：“自然语言复盘 + LLM 抽取结构化字段”可行，但必须配合解析容错。

### 生成约束
- 所有输出引用来源文档片段（策略文档/书籍原文/行情数据），增强可信度
- 所有投资建议强制附加免责声明

## 替代方案
- **结构化策略表单**（用户选择策略模板、勾选买卖条件）：被否决。结构化表单难以表达个人化的交易心法（如"熊市轻仓只做龙头"这类经验性策略），且录入成本高；文档导入复用现有 RAG 管道，成本最低、表达力最强。
- **结构化表单录入复盘**（逐字段填买卖价、原因）：被否决。普通投资者不会逐字段填表，自然语言 + LLM 抽取更贴合真实写作习惯，且保留原文情绪与上下文。
- **为每个用户单独建向量集合**：被否决。Milvus 中通过 `owner_id` 标量字段过滤即可实现隔离，避免集合数量膨胀。
- **自动抓取券商持仓**：被否决。个人开发者难以获得券商 API 授权，实现成本高，列为远期扩展。

## 后果
### 正面
- 完全复用现有文档导入 RAG 管道，个性化能力几乎零新增基建。
- 文档形式表达策略，贴合真实投资者"写心得、读书学习"的习惯。
- 自然语言复盘 + LLM 抽取，降低录入门槛，同时保留结构化数据供统计与检索。
- 三路召回（个人策略 + 公共书籍 + 复盘）结合独立行情上下文，使回答既有个人风格又有理论依据。

### 负面/风险
- 用户策略文档质量参差不齐，召回噪声可能影响建议质量，需依赖 Rerank 重排序和断崖检测控制。
- 策略文档是"知识"而非"可执行规则"，系统无法严格执行条件触发（如 RSI<30 必提醒），只能语义匹配提示，存在提示不精准的风险。
- 复盘的 LLM 抽取可能出错（价格、代码识别错误），需保留原文以便人工校正。
- 复盘记录依赖用户主动输入，长期留存率可能不足。
