# ADR-0006: 系统架构与技术栈调整

## 状态
已提议

## 背景
前 5 个 ADR 已确定行情引擎、个性化投资助手、风险评估、脱敏合规等能力。本 ADR 将它们串联为可落地的系统架构，服务于个人使用阶段（后续可逐步演进至上线版本）。

## 决策
### 服务边界：保持现有双服务结构，新增能力内嵌
- **导入服务（8000）**：维持现有文档导入、PDF/Markdown 解析、向量化、Milvus 入库能力，复用用于策略文档和知识库文档的入库。
- **查询服务（8001）**：维持现有检索+重排序+SSE 流式对话能力，新增：
  - A 股行情引擎（调用免费行情接口，收盘后抓取，写入 MongoDB market_quotes）
  - 定时调度器（APScheduler，每日收盘后触发行情抓取 + 每日投资摘要生成）
  - 个性化投资助手查询路由（三路召回：personal/knowledge/review + 行情，RRF 融合）
  - 个股风险等级自动附带（查询个股时返回）
  - 脱敏（写入前 + 返回前）与免责声明强制附加
- **不拆分新服务**：个人使用阶段双服务足够，避免多服务运维复杂度。

### 每日投资摘要的触达方式：拉取展示，不主动推送
- 收盘后定时任务生成每日投资摘要，存入 MongoDB daily_summaries 集合。
- 用户打开前端页面时，拉取并展示当日摘要。
- 不集成邮件/微信/Telegram 等主动推送通道，个人使用阶段不需要。

### 用户体系：单用户模式，无登录注册
- 固定 user_id（如 default_user），所有 Milvus 向量通过 owner_id 过滤隔离。
- 不做登录、注册、权限管理；后续上线部署时再引入认证体系。

### 前端形态：在现有 HTML 基础上扩展
- 复用 knowledge/front/chat.html 基础页面，新增：
  - 行情与大盘位置展示区块
  - 每日投资摘要列表
  - 交易复盘自然语言输入框
  - 个股风险等级标签
- 不重做前端（React/Vue 等），避免重构成本。

### 技术栈变更（增量）
| 层 | 原有 | 新增/调整 |
|---|---|---|
| 后端 | FastAPI + LangGraph | + APScheduler（定时行情抓取/摘要生成） |
| 行情数据 | 无 | 免费 A 股行情接口（东方财富/新浪/腾讯） |
| 向量库 | Milvus | 复用，新增 `owner_id` 与 `doc_type` 标量过滤字段，类型为 `personal`/`knowledge`/`review` |
| 文档库 | MongoDB | 复用，新增 `market_quotes`、`trade_reviews`、`daily_summaries` 集合 |
| 对象存储 | MinIO | 复用，存策略文档 PDF |
| 前端 | HTML + JS | 原地扩展页面模块 |

## 替代方案
- **拆分微服务（行情服务/调度服务/推送服务等）**：被否决。个人使用阶段无必要，双服务足够支撑。
- **主动推送摘要（邮件/微信等）**：被否决。拉取展示更简单，且个人使用时用户主动打开前端即可。
- **现在就做多用户登录**：被否决。个人使用阶段单用户足够，登录体系增加前后端复杂度。
- **前端重做为 React/Vue**：被否决。现有 HTML 基础足以支撑扩展模块，重做成本高。

## 后果
### 正面
- 零新增服务，运维成本低，个人开发者可独立维护。
- 复用现有 RAG 管道与双服务结构，开发工作量小。
- 单用户+拉取模式，避免认证与推送通道的复杂度。

### 负面/风险
- 定时任务依赖查询服务进程存活，若服务重启会错过当日收盘抓取（可容忍，次日手动触发即可）。
- 单用户模式无数据隔离需求，后续上线多用户时需重构 Milvus 过滤与 MongoDB 索引。
- 前端原地扩展可能导致页面结构臃肿，后续可考虑拆分页面。
