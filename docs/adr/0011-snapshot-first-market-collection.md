# ADR-0011：先保存全目录快照，再补采历史缺口

状态：已接受（2026-11-28，用户要求继续完成下一步，全市场验收暴露补采阻塞）。

## 背景

ADR-0008、ADR-0010的采集器在每50只证券内先处理全部历史备用，再保存该批行情。真实目录含无法取得目标日数据的证券，少量逐只备用请求会阻止后续批次运行；若预算耗尽，该批已取得但尚未返回的有效快照也无法保存。增加备用来源不能解决这种处理顺序造成的覆盖损失。

## 决策

1. 全市场分两阶段：先遍历待处理目录，每50只请求腾讯快照并立即核验、保存；全部快照批次完成后，再按东方财富 → BaoStock → 腾讯历史逐只补采仍缺失的证券。
2. 每只历史补采成功后立即保存，下一只超时或来源失败不丢弃已有结果。历史请求仍覆盖全部缺失项，直到既有20分钟总预算或停止条件触发，不因为缺失数量多而禁用备用。
3. 保持原API、来源顺序、价格/单位/身份规则、原子仅插入、全局租约和停止预算。快照缺失在历史处理前计入pending；已经确认格式或身份异常的存量记录计入失败，不以补采覆盖，应通过单股刷新核对。
4. 超时或中断仍返回failed并保留已保存行情，未完成项不会被计为成功。completed/partial含义不变，不把来源目录覆盖当作交易所全集认证。
5. 真实验收增加来源、交易所、可选字段统计；可主动中断首批后补采，验证跳过已有证券且值不变。使用独立随机集合，失败保留报告；线程未停止时不边写边删，核实原进程退出后提供限定该报告的清理入口。

## 验证边界

快照优先改善有限预算内可保存的行情范围，不保证全部缺失有可用历史；免费目录中的停牌、退市或更名原因必须有证据，不能通过跳过未知证券提高覆盖率。真实历史日期重采不等于持续多个实际交易日运行；本轮不增加定时监控或金融规则回测。
