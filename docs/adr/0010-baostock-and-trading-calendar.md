# ADR-0010：独立历史日线来源与交易日历

状态：已接受（2026-11-28，用户要求继续推进免费数据源改进）。

## 背景

ADR-0009已补腾讯历史日线，但来源不提供可核实的历史日涨跌幅，单股波动率因此受限。原自动任务只按周一至周五触发，法定休市日会进行无效采集。下一步优先实测独立来源，而不是继续增加同一供应商的SDK封装。

## 决策

1. 引入 `baostock==0.9.4`，匿名公共接口无需用户API key。只接入经过身份核验的沪深A股；北交所920样本返回无标的/无效代码，明确跳过并继续既有来源。
2. 单股及全市场缺失补采顺序调整为东方财富日线 → BaoStock日线 → 腾讯日线；单股最终仍可退回腾讯最新快照。该顺序补充ADR-0009，不改变全市场腾讯批量快照首选。
3. `adjustflag=3`固定不复权；价格元、量股、额元、`turn/pctChg`百分数直接保留来源精度。`peTTM`只保存于raw，不放入表示动态PE的`pe`。仅同日同身份同OHLC、成交量差不超过100股且金额差不超过1元的腾讯收盘快照可补充当日非空估值；腾讯PB缺失时保留BaoStock的PB，混合来源标记 `baostock+tencent`，raw逐字段保留来源。历史PE缺失继续显示。
4. SDK使用进程级全局socket且没有本项目所需的统一时限，因此每次请求放到独立子进程：仅固定的日线/日历操作、5秒socket超时、20秒整体时限，超时杀死并回收子进程；同进程串行、1秒间隔、60秒失败冷却、排队最多2秒。本轮只尝试一次SDK请求，再走下一个来源，不建立无限重连后台线程。
5. 日历校验完整自然年、日期唯一、状态0/1，成功缓存24小时。格式校验失败不缓存成功结果，日历请求冷却60秒，不阻止其他历史日线请求。日历缓存锁排队最多2秒，超时不发新请求、返回未知；SDK入口另有自己的2秒排队上限。`GET /market/calendar?date=YYYY-MM-DD`返回日期、是否交易日、来源、检查时间及缓存状态；来源失败返回`is_trading_day=null`，不推断为休市。仅支持当前日期前后366天。
6. 自动摘要和16:00全市场任务只在日历明确休市时跳过；日历未知或意外失败时继续由实际目标日行情核验。手动生成与采集保持现有日期/行情检查，日历不把停牌、延迟或未收盘数据变成有效行情。

## 后果

沪深备用日线能直接提供来源日涨跌幅，具备计算20日波动率的数据基础；这不等于风险阈值经过收益回测。独立子进程增加启动成本，但避免共享SDK连接串线和不可控阻塞。全市场仍受20分钟预算约束，备用SDK不保证整市场时效或完整性。

只记录数据来源与能力，不声称知道BaoStock内部上游构成。日历无需单独数据库；重启重新读取来源。没有新增券商连接、交易执行、财务分析或登录审计。
