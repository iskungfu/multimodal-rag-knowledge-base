# ADR-0013：局部故障隔离与转换后数据契约

状态：已接受（2026-11-28，用户要求继续修复并参考 GitHub 金融平台优化系统）。

## 背景

档案读取异常曾中断整条投资查询，使已核验行情被通用错误覆盖。合法的 10000 字复盘在脱敏后可增长为 10006 字，保存成功但查询因长度被过滤。真实摘要验收曾出现两次 `ValueError`，现有报告不能区分响应、结构、来源或原文校验失败。

GitHub 官方源码对照见 [金融平台设计研究](../research/financial-platform-design-2026-11-28.md)：借鉴 OpenBB 的转换与标准模型、LEAN 的风险职责分离、vn.py 的来源和生命周期归属。它们提供设计参考；本项目行为仍由自己的需求及回归验证。

## 决策

1. 档案失败只关闭范围无法确认的个人策略检索；继续公共知识、复盘及独立行情。回答明确标记档案不可用，不能回退到全部个人策略。每轮重新读取，历史回答不随档案恢复改写。
2. 复盘新增、编辑的服务入口先脱敏，再按共享的 10000 字符完整原文契约校验。输入本身也受此上限约束。失败返回 422，已有记录及索引不变；有效临界文本必须能索引和完整引用。索引领取、展示及检索同样核验全文，旧超长记录显示 `invalid_text` 和编辑提示，阻止无效索引写入；保留原文可读，通过用户编辑纠正，不自动截断交易条件。
3. 摘要模型失败使用固定原因码区分响应不完整、格式、来源、原文和行情依据错误；存入失败记录及验收报告，日志不携带原文或任意异常信息。重新开始和成功时清空错误码，失败保留上次成功结果，继续严格校验后才发布。

## 后果与验证

这些改动强化 ADR-0003、ADR-0005 和 ADR-0007 的原有约束，不改变 ADR-0006 的双 FastAPI、HTML 和 LangGraph，也不引入交易执行或新基础设施。`QueryRuntime` 继续遵守 ADR-0012。

验证使用内存存储和注入故障：同步/SSE/历史一致、档案恢复及模式范围；复盘新增/编辑的无副作用拒绝与临界全文召回；摘要各失败码、原文不泄漏、旧结果保留和恢复。真实验收使用随机独立库及 UUID 集合，保留首次失败报告。通过复测不等于历史根因已被证明。
