# ADR-0012：查询运行统一装配与资源归属

状态：已接受（2026-11-28，用户选择架构候选 1，并采用推荐方案）。

## 背景

查询、摘要、复盘、档案和采集的工厂分别缓存连接与实例。验收脚本通过修改环境变量、覆盖依赖及替换全局历史集合重建装配，新增入口容易遗漏：风险验收的浏览器应用曾开放未覆盖的档案和全市场采集入口，向测试库中的固定集合写入，而退出仅清理 UUID 行情和历史集合。

问题在于存储命名、实例生命周期和清理归属分散在多处。仅增加依赖覆盖或手写删除列表，不能让下一个新增入口自动遵守同一规则。

## 决策

1. 将查询运行作为一个 module，由 `knowledge/runtime.py` 的 `QueryRuntime` 提供 interface。`RuntimeConfig` 在构造时取得存储地址、集合名称、开放入口和调度配置；业务 implementation 通过运行实例获得依赖，不在请求中重新决定存储位置。
2. 每个 `create_app()` 拥有独立查询运行，依赖从 `app.state.runtime` 读取。运行内用锁延迟装配，同一摘要实例只有一个生成槽；构造失败不缓存失败实例，后续调用可重试。指数行情直接装配，不借每日投资摘要工厂取得。
3. 正式应用的 lifespan 负责关闭自己的查询运行。调用方显式传入运行时，应用借用它：lifespan 只停止活动，连接与资源由外层调用方最终关闭，支持验收中多次 TestClient 及随后浏览器运行。独立调用与导入进程保留默认装配兼容入口。
4. 验收仍必须指定与业务库、Mongo URI 默认库及系统库不同的 `AFK_TEST_DB_NAME`。脚本生成 UUID 前缀，所有可能写入的集合使用该前缀；使用前检查重名，并在创建或写入前登记归属。风险验收的 `--rag-query` 可只读借用既有公共知识和商品名向量集合，借用资源不进入删除清单。
5. 验收开放入口由功能集合决定，未开放的入口不挂载，返回 404 且不装配存储。风险验收开放聊天、行情、日历；摘要主机验收另开放复盘、摘要、策略；投资助手验收再开放档案。三者均关闭全市场采集。摘要二维存储探针仅开放摘要入口。聊天内部所需的档案、指数或复盘仍使用本轮运行的资源。
6. 退出先拒绝新请求、停止调度并等待活动请求及同步查询线程，通知和等待采集 worker 停止，然后清理自有资源、任务状态及 SSE 队列，最后关闭连接。等待超时保留资源，返回失败，允许任务结束后再次关闭；不边写边删。调度器启动中途失败也执行退出处理。清理按登记的准确名称进行，失败进入验收报告并影响退出码。
7. 正式运行永不删除集合。运行归属只解决同进程装配与验收生命周期，不替代用户身份认证；任务状态仍使用已有存储，以运行登记的任务 ID 限制查询与清理。
8. 每个查询运行为 Milvus 客户端指定独立随机连接 alias。真实验收发现所用 PyMilvus 会让相同地址的默认客户端共享底层连接，关闭其中一个会使另一个失效；独立 Python 对象不足以保证连接归属。调用方注入的客户端也须由调用方提供独立连接。

## 替代方案与后果

仅集中配置和清理清单、保留分散工厂，会继续要求脚本替换全局缓存，或在每个入口重复传递相同依赖，未能通过 deletion test。因此选择统一装配，在一个 seam 后集中连接、命名及生命周期；MongoDB/Milvus adapter 和既有业务实现保持独立。

这个 module 的 depth 来自较小 interface 隐藏完整装配关系，新增入口只需使用运行实例。测试获得 leverage：通过两个真实 FastAPI 应用即可核对同会话、同档案、任务状态和清理隔离，提升 locality；无需在每份脚本维护一套覆盖列表。代价是 `runtime.py` 必须随新的存储依赖和后台活动一同更新，外层借用者必须最终调用 `close()`。

ADR-0006 的双 FastAPI 进程、HTML 和 LangGraph 不变；退出顺序遵守 ADR-0011。不改变风险规则、空策略模式、复盘索引发布或验收观察器。长期调度和真实外部存储/模型的可用性仍由各自验收负责。

## 验证

`knowledge/test/test_runtime.py` 使用内存存储并禁止网络，覆盖两应用隔离、关闭入口、资源归属、借用资源保留、并发首次装配、构造失败重试、调用方复用、请求取消后线程继续执行，以及调度器启动失败后的清理。三个验收脚本沿用相同装配，同时保留各自已有的探针与观察器。

既有 `verify_rag.py` 的查询侧也显式使用本轮运行，观察器挂到实际执行的图；其公共文档导入侧仍沿用原装配和临时资源管理。查询运行将该脚本管理的公共集合记为借用，先停止查询，再由脚本清理导入资源。
