# 全市场收盘采集

查询服务新增全市场采集，覆盖来源目录中可核验的沪深 A 股和北交所现行 `920` 股票代码。它负责积累每日行情；每日投资摘要仍围绕双指数与最多20只关注股票，关注数不再限制行情采集范围。

## 使用

在聊天页展开“全市场收盘行情采集”，选择已收盘日期，点击“采集 / 补齐缺失”。页面显示持久进度、总数、已保存数、缺失与源目录排除；部分失败后再次点击，只补目标日缺失的证券。成功状态表示当前目录的采集完成，不等于免费源对交易所全集的认证。

```bash
curl -X POST http://localhost:8001/market/collection/run -H 'Content-Type: application/json' -d '{"date":"2026-11-27","retry":true}'
curl http://localhost:8001/market/collection/latest
curl http://localhost:8001/market/collection/2026-11-27
```

POST返回202与 `started/record`；重复的已完成日期默认不重新运行。`retry=true`重新检查目录并补缺，不强制覆盖所有已保存价格。正在采集时其他启动请求返回409。GET不存在记录时 `record=null`；存储失败返回503。日期上限取 Asia/Shanghai 当前已收盘日期，最长向前366天，未来、周末和未收盘当天拒绝。

## 调度与恢复

`MARKET_COLLECTION_ENABLED=1`启用每个工作日16:00自动采集。未配置时跟随 `DAILY_SUMMARY_ENABLED` 的启用状态；可以分别开启或关闭。只在 FastAPI lifespan 启动任务，无导入模块后台副作用。摘要默认15:30生成；两者独立运行，摘要所需行情仍按实际日期自行获取。

服务离线期间没有补采保证；恢复后可手动补采。工作日不等于交易日，自动任务先检查BaoStock交易日历，只有明确休市才跳过；日历未知或故障仍继续原行情核验流程。已核实休市时不创建采集失败记录，手动补采接口保持原日期规则。缺少目标日真实行情时不会改写旧日期。批量快照主要覆盖最近收盘日，历史补采取决于来源仍可提供的数据；不能保证多年历史完整。

`market_collection_runs`保存单日进度、来源目录、成功数、缺失原因和重试次数；`market_collection_locks`保存全局租约。租约180秒，30秒续约，20分钟执行预算。崩溃任务在读取或下次启动时过期为失败，已保存 `market_quotes` 保留。跨进程锁防止重复大批抓取，失效worker不能发布新状态或释放别人的锁。状态写入失败可能暂时显示旧进度，恢复后可重试。

采集写库只用原子插入缺失记录，不覆盖已经存在的同代码同日期行情，防止旧worker恢复后覆盖新价格。写前再次校验租约；写后读取实际存储值再核算成功数。已有记录无效或身份不符时列为失败，使用单股刷新接口另行核对，而不是静默覆盖。

## 数据口径

东方财富分页目录优先，新浪备用；每页数量、总数和代码唯一性均检查。原始目录可能包含非股票或旧代码，`reported_total`保留源数量，`excluded_codes`保留排除代码。支持 `302` 创业板代码；北交所问答额外核验证券检索中的京A类型，不能仅凭数字前缀把新三板当股票。

腾讯快照每批50个，每个独立核验代码、市场、名称、收盘日期与时间。先遍历全目录快照并逐批保存，再逐只补采缺口，避免少量慢备用请求阻塞后续批量行情；每只历史补采成功立即保存。单位与现有单股接口一致，价格元、成交量股、成交额元、百分数不再缩放，PE使用动态PE。腾讯688/689量原本为股，不再统一乘100。缺失证券逐个尝试东方财富目标日日线、BaoStock不复权日线、腾讯不复权历史日线；北交所跳过BaoStock。HTTP每请求最多两次，BaoStock使用单次受限子进程；两个阶段共同受整轮20分钟预算、限速及冷却控制。跨日补采也不因缺失数量多而跳过历史源。保留来源原始行情字段用于核对；历史涨跌幅或估值不足时继续计入可选字段不足，不推算填充。详见ADR-0009、ADR-0010、ADR-0011及 `docs/baostock-and-calendar.md`。

进度分别记录待处理与已失败；快照缺失且还未进行历史补采的证券计入待处理，终止时将未处理项列为未完成。已保存数据中缺失 PE/PB、换手率等可选字段时显示单独的数据不足计数；“采集完成”不代表所有可选指标完整。

名称比较只归一化全角字符与空白，ST标记仍参与核验。停牌、退市、名单名称不一致、源缺失或旧日期都不会生成虚假当日记录，而是计入缺失。没有可靠状态证据时不猜测缺失原因。

`completed`：主源目录通过完整分页、无未识别代码、所有支持证券都已入库。`partial`：存在缺失、目录排除或使用备用名录。`failed`：无有效目标日行情、超时或运行失败。任何状态都不代表已经回测风险阈值或承诺免费源持续可用。

真实验证命令：在独立 `AFK_TEST_DB_NAME` 下运行 `python scripts/verify_market_collection.py`，报告分别记录功能检查、真实覆盖和资源清理。长期跨交易日运行、退市/更名历史映射仍需独立验证。

使用 `python scripts/verify_market_collection.py --resume` 可在首批写入后主动中断，再通过同一采集API补采。报告记录中断时已保存数、重试实际请求数、已有行情是否保持原值，以及各来源保存数、沪深京目录覆盖、逐字段缺失数和未取得行情的代码/名称。这里的覆盖率以本次来源目录为分母，不是交易所全集或全部指标的完整率；缺失理由没有证据时不推定为停牌或退市。

恢复验收会重新读取目录，各次采集分别受原20分钟预算限制；整个验收可能超过20分钟。异常退出先停止并等待采集线程，再删除本轮随机测试集合；线程未停止时保留集合并标记清理失败，避免边写边删。不会改写业务行情，也不会启动长期监控任务。

若报告记录清理失败，原验收进程退出后，可在同一主机、相同独立测试库配置下执行 `python scripts/verify_market_collection.py --cleanup-run market_collection_<12位编号>`。工具校验报告编号、主机、测试库和原PID不存在，再删除该编号的三个固定后缀集合；原进程仍在运行或PID被复用时拒绝。清理重试保留原验收失败结论，只更新清理结果。历史报告缺少这些身份信息时不能使用该入口。
