## Problem Statement

普通投资者在做投资决策时，往往需要同时查看 A 股行情、回顾自己的交易经验、参考经典投资理论，但现有工具分散、缺乏个性化。当前项目是一个通用 RAG 知识库系统（文档导入、向量检索、重排序、SSE 流式问答），无法满足“结合个人交易策略 + 实时行情 + 投资知识库”给出个性化投资提示的需求。同时，金融场景涉及敏感个人信息和合规风险，需要脱敏与免责声明机制。

## Solution

将现有通用 RAG 知识库转型为**个人投资顾问平台**（面向普通投资者，暂时聚焦 A 股、个人使用阶段）。在保留现有 RAG 管道（BGE-M3 向量检索、BGE-Reranker 重排序、SSE 流式对话、FastAPI 双服务、Milvus/MongoDB/MinIO）的基础上，新增：

- **A 股行情引擎**：免费渠道优先获取 A 股日线行情，交易日当天收盘后更新，存入 MongoDB。
- **个性化投资助手**：用户通过导入策略文档（PDF/Markdown/文字）和自然语言复盘记录构建个人策略库；查询时三路召回（个人策略 + 公共知识库 + 复盘记录），RRF 融合后结合独立行情数据生成个性化建议。
- **每日投资摘要**：收盘后定时生成，结合行情 + 个人策略 + 公共知识，用户拉取查看。
- **个股风险评估与大盘趋势**：基于行情指标自动计算低/中/高风险等级，融入查询与摘要，不单独推送。
- **脱敏与合规**：写入前 + 返回前双端脱敏；每次 AI 回答强制附加免责声明。

## User Stories

1. As an 普通投资者, I want to 上传我的投资策略文档（PDF/Markdown/心得文字）, so that 系统能理解我的交易风格并在建议中引用。
2. As an 普通投资者, I want to 上传经典投资理财书籍到公共知识库, so that 投资建议有理论依据。
3. As an 普通投资者, I want to 用自然语言写交易复盘（像写交易日记一样）, so that 我不用填结构化表单也能记录交易教训。
4. As an 普通投资者, I want the 系统从我的自然语言复盘中自动抽取股票代码、买卖价格、原因、教训、情绪标签, so that 复盘可以被结构化存储和后续检索。
5. As an 普通投资者, I want 复盘抽取失败时系统仍保留我的原文, so that 我的记录不会丢失且我可以人工校正。
6. As an 普通投资者, I want to 查询某只 A 股是否适合买入, so that 我能得到结合我个人策略和当前行情的建议。
7. As an 普通投资者, I want 系统在回答中明确引用信息来源（个人策略/公共知识库/行情数据）, so that 我能判断建议的依据是否可信。
8. As an 普通投资者, I want 查询个股时自动看到该股的风险等级（低/中/高）, so that 我能快速判断当前买入时点风险。
9. As an 普通投资者, I want 看到大盘当前位置风险（高/中/低）而不是牛熊市判断, so that 我能理解当前时点风险而不被阶段性预测误导。
10. As an 普通投资者, I want 每日收盘后收到一份每日投资摘要（拉取查看）, so that 我不用逐个查股票也能了解当日关注标的和操作提示。
11. As an 普通投资者, I want 每日投资摘要结合我的个人策略, so that 摘要是针对我而不是通用市场评论。
12. As an 普通投资者, I want 每日投资摘要包含大盘位置简评、关注个股风险提示、操作建议, so that 我一眼看懂当天重点。
13. As an 普通投资者, I want 系统自动获取 A 股日线行情（价格、涨跌幅、成交量、PE、换手率等）, so that 我不用手动输入行情指标。
14. As an 普通投资者, I want 行情数据在收盘后自动更新, so that 我次日查看时数据是最新的。
15. As an 普通投资者, I want 系统在我上传文档或输入复盘时自动脱敏敏感信息（姓名、手机号、身份证号、银行卡号、持仓金额）, so that 我的隐私数据不会被明文存储。
16. As an 普通投资者, I want 系统在返回 AI 回答前再次脱敏, so that 模型不会在回答中泄露原始敏感信息。
17. As an 普通投资者, I want 每次 AI 回答结尾都看到免责声明, so that 我清楚这是参考信息而非投资建议。
18. As an 普通投资者, I want 系统用通俗易懂的语言回答, so that 我作为非专业投资者也能理解。
19. As an 普通投资者, I want 我的个人策略文档只对我可见, so that 我的交易心得不会被其他人看到。
20. As an 普通投资者, I want 公共知识库（经典投资书籍）对所有使用者可见, so that 大家共享理论基础。
21. As an 普通投资者, I want 我的历史复盘教训能在后续查询中被召回, so that 系统能提醒我不要重复犯错。
22. As an 普通投资者, I want 系统支持三路召回（个人策略 + 公共知识库 + 复盘记录）并结合行情数据回答, so that 建议既个性化又有理论和数据支撑。
23. As an 普通投资者, I want 在个人使用阶段无需登录注册即可使用, so that 我能快速开始使用。
24. As an 普通投资者, I want 在现有聊天页面看到每日摘要和风险提示, so that 我不需要切换多个复杂页面。
25. As an 普通投资者, I want 系统在行情数据源不可用时有备用源或明确提示, so that 单一数据源故障不会导致功能完全不可用。
26. As an 普通投资者, I want 个股风险评估基于涨跌幅、换手率、近N日波动率、PE、成交量异常自动计算, so that 风险判断有一致的指标依据。
27. As a 开发者, I want 行情抓取通过 adapter 抽象层实现, so that 未来可以从免费源切换到付费源而不改业务逻辑。
28. As a 开发者, I want 复盘 LLM 抽取有 JSON 解析容错与降级保留原文, so that LLM 输出格式波动不会导致数据丢失。
29. As a 开发者, I want Milvus 中文档按 owner_id + doc_type（personal/knowledge/review）隔离, so that 三路召回可以按范围过滤。
30. As a 开发者, I want 每日摘要生成作为收盘后定时任务运行并写入 MongoDB, so that 前端拉取展示简单可靠。

## Implementation Decisions

以下决策基于需求讨论与 ADR（0001-0006）。2026-11-27 启动审阅更正：原型仅是探索，不等于模块验收；GitHub 旧 Issue 中照搬的字段公式和“每日一次不受限”断言不得直接作为测试期望。

- **架构形态（ADR-0006）**：保持现有双服务（导入 8000 + 查询 8001）。行情引擎、APScheduler 定时任务、每日摘要生成、风险评估、脱敏、免责声明全部内嵌在查询服务；导入服务复用现有文档导入管道。单用户模式固定 `user_id=default_user`，无登录。前端在现有 `knowledge/front/chat.html` 基础上原地扩展。
- **行情数据源与存储（ADR-0002）**：免费渠道优先（东方财富主，新浪/腾讯备）。交易日收盘后抓取当日行情，预留实时扩展。目标字段包含代码、名称、价格、涨跌幅、成交量、成交额、换手率、PE/PB、市值和 OHLC。正式实现必须校验具体接口的字段语义、精度与响应编码，不照搬原型公式。RemoteDisconnected 的原因未确定，任何请求频率都需要超时、重试上限及失败降级。历史日线与快照分开适配。存储复用 MongoDB 新集合 `market_quotes`，`(code, date)` 唯一索引；缺失估值字段不得编造。
- **个性化投资助手（ADR-0003，原型 2/3 探索）**：策略通过文档导入形成（PDF/Markdown/文字），不做结构化表单。三层知识隔离：Milvus 通过 `owner_id` + `doc_type`（`personal`/`knowledge`/`review`）过滤。双模式：每日投资摘要（主动生成、拉取展示）+ 按需查询（三路召回 RRF 融合）。复盘记录为自然语言输入，LLM 自动抽取结构化字段（股票代码、买卖价格、买卖原因、反思教训、情绪标签），原文+抽取结果存 MongoDB `trade_reviews`，同时向量化入 Milvus（`doc_type=review`）。解析失败降级保留原文，抽取失败不阻塞保存。原型 2 的 6/6 JSON 解析成功只证明格式可解析，需另外校验交易计划与真实成交、缺失字段和代码冲突。原型 3 仅手工拼接上下文，尚未验证 Milvus 检索、RRF 或 rerank。
- **个股风险评估与大盘趋势（ADR-0004）**：风险指标全部自动从行情获取（涨跌幅、换手率、近N日波动率、PE、成交量异常），输出低/中/高三档。大盘仅输出“当前位置风险（高/中/低）”，不做牛熊/震荡阶段判断。风险等级融入个股查询回答与每日摘要，不单独推送。
- **脱敏与合规（ADR-0005）**：脱敏字段（简易版）：姓名、手机号、身份证号、银行卡号、持仓金额。双端脱敏：写入前 + 返回前。脱敏方式：手机号前3后4、身份证前4后4、银行卡后4、姓名保留姓、金额保留数量级。每次 AI 回答强制附加免责声明：“以上信息不构成投资建议，投资有风险，入市需谨慎。”暂不做审计日志。
- **每日摘要（ADR-0003/0006，原型 4 探索）**：收盘后定时生成，存 MongoDB `daily_summaries`，前端拉取展示。原型 4 仅用模拟输入生成文本，未验证调度、存储或策略适用条件，正式实现需分别验收。

## Testing Decisions

- **好测试的标准**：只测外部行为，不测实现细节；通过公开接口/服务边界验证输入输出与副作用（API 响应、MongoDB/Milvus 写入结果、生成文本包含必要约束）。
- **行情 adapter**：用已核实的原始 HTTP 样本测试字段映射、单位、响应编码、缺失值、超时及备用源切换；单元测试不依赖真实外网。另行记录真实日线抓取和 MongoDB 写入的集成验证结果。
- **复盘抽取**：用固定自然语言样本测试 LLM 抽取结果的 JSON 解析、字段缺失容错、解析失败降级保留原文；LLM 调用可 mock。
- **三路召回与融合**：构造 personal/knowledge/review/market 四类上下文，验证召回过滤（owner_id+doc_type）、融合回答包含来源引用与免责声明。
- **风险评估**：给定行情快照，验证低/中/高分档规则输出稳定；验证大盘只输出当前位置风险不输出牛熊判断。
- **脱敏**：覆盖姓名/手机/身份证/银行卡/金额的写入前与返回前脱敏；验证双端都生效。
- **每日摘要**：验证定时任务生成结果写入 `daily_summaries`，摘要包含大盘、个股风险、个人策略、免责声明。
- **Prior art**：复用现有 `knowledge/test` 与现有导入/查询服务测试模式（如有）；新增测试与现有 FastAPI/pytest 风格保持一致。

2026-11-28 用户确认的个人使用版补齐：每日摘要公共知识引用、自然语言复盘编辑纠错、策略模式切换、风险偏好档案。实现契约见 ADR-0007 与 `docs/personal-settings.md`；以下上线与自动交易等边界继续保持。

2026-11-28 后续补齐：公共文档新上传的写入前脱敏、原件/图片不持久备份，全市场收盘采集及进度重试。ADR-0008 明确 PDF 临时解析、历史资产、免费源完整性和跨日补采边界；逐条现状以 `docs/requirements-acceptance.md` 为准。本文原型章节保留探索时点，不代表当前仍未实现。

## Out of Scope

- 自动获取券商持仓/交易记录（依赖券商授权，暂不实现）。
- 实时盘中行情推送与分钟级交易信号（当前交易日当天收盘后更新）。
- 多用户登录、权限管理、审计日志（个人使用阶段不做，上线前再加）。
- 主动推送通道（邮件/微信/Telegram）；当前仅前端拉取展示。
- 牛熊市阶段性判断功能（只做大盘当前位置风险）。
- 前端重构为 React/Vue（在现有 HTML 基础上扩展）。
- 付费专业行情源接入（上线推广后再切换）。
