# 个性化投资助手

聊天 `POST /query` 自动区分投资问题和已有商品知识问题。投资问题使用 `personal`、`knowledge`、`review` 三路向量检索，行情作为独立上下文。此处遵循 GLOSSARY、ADR-0003 和更新后的规格，修正 Issue #7 旧正文将行情列为向量一路的描述。

## 使用

1. 通过现有策略入口导入 PDF、Markdown 或文字，形成个人策略库。
2. 公共投资资料通过原公共知识导入入口入库。
3. 在“交易复盘”输入自然语言日记。文本保存、字段抽取和检索索引的状态分别显示；索引失败仍保留文本，可按记录重试。无需逐字段填写交易表格。
4. 在聊天中提问，例如“结合我的策略和复盘，平安银行000001有哪些风险需要核对？”或“我上次追高的教训是什么？”

明确个股问题先核实名称与代码，冲突先澄清。查询成功时始终展示确定性行情风险、实际日期、来源与不足；模型不能改写风险等级。大盘问题复用双指数数据，缺少目标日数据时说明无法判断，不将股票000001当上证指数，不输出市场阶段分类。

简短追问仅沿用最近一条用户消息保存的服务端投资上下文，最多读取四条历史消息、保留1500字符上下文。历史 AI 回答不进入证据库，换成商品话题或身份冲突后不沿用旧证券。旧历史没有此上下文时，需要重新明确问题。

`POST /reviews/{review_id}/index` 为已有记录建立或重试索引。每条记录使用180秒租约，每10分钟最多尝试3次，失败后至少等待30秒；界面显示可重试时间，届时刷新即可。处理中进程中断会在租约过期后显示可恢复状态。更新抽取结果会使旧索引失效；旧 worker 不能发布或删除新版本。发布结果不确定时保留向量，由后续按记录重试处理。

复盘按实际 BGE token 预算切片，查询命中后恢复同一记录的完整脱敏原文供核对，避免将断开的前提当作行动建议。同一复盘多个切片命中时仅展示一次。

## 检索与回答

- `STRATEGY_COLLECTION` 默认 `strategy_chunks_v1`，限定 `personal/default_user`，仅召回 MongoDB 状态为 completed 的策略文档。
- `CHUNKS_COLLECTION` 使用现有公共库，限定 `knowledge/public`。旧公共 schema 仅延续已有服务端认可范围，不允许个人资料回退到无隔离旧库。
- `REVIEW_COLLECTION` 默认 `review_chunks_v1`，限定 `review/default_user`，同时校验 MongoDB 发布版本、manifest、切片标识及内容 hash。
- 三路各最多保留6条，RRF 使用来源类型、collection、文档或复盘ID与 chunk_id 组成去重键，默认常数60。后续真实 BGE reranker 排序及断崖截断保留来源信息，并保留各可用来源的最佳候选。
- 模型根据问题和独立行情上下文，仅从实际候选选择资料来源编号，无须重新抄写原文或行情引用。服务端验证编号并附上完整候选原文、适用前提与来源；行情引用由服务端独立提供。模型不能自由编造价格、成交、持仓或引用。
- 对个人策略提示核对前提，对公共知识提示核对理论依据，对复盘提示检查重复失误。计划、挂单和未知状态始终不等同于已成交；策略中的牛熊条件不能视为当前已满足。

单路为空与故障分别显示；全部没有依据时不生成貌似个性化的结论。重排失败保留 RRF 顺序；模型选择失败展示检索原文，并明确未生成个性化结论。行情独立保留，不被个人资料故障覆盖。

模型选择单次请求超时90秒，最多尝试两次；重试仍只使用原始可信候选，失败响应不作为新证据或展示内容。两次均失败时立即采用有据降级，不循环重试。

服务端统一执行最终脱敏及唯一免责声明。SSE 在终稿保护后发送完整 delta 和 final，非流式、status、history 返回同一终稿。资料内自行编写的 chunk 引用不会作为可信引用，只有实际检索结果可进入引用白名单。

## 运行边界

仍为单用户 `default_user`，未新增登录或多租户身份认证。未接券商、未执行交易、不自动推断当前持仓、不发送独立推送，也不新增审计日志。脱敏仍为已有基础规则，不保证识别所有自由文本中的个人信息。

资料相关性、模型选择和初始风险规则均有局限；展示依据不代表策略已通过回测或具备盈利能力。CPU 首次加载 BGE 和 reranker 较慢。验收必须使用显式独立测试库、自建文本和唯一向量集合；关闭每日调度，避免写入业务库。

真实三路与浏览器验收入口：`scripts/verify_investment_assistant.py --host`。旧商品 PDF/SSE、旧 schema 和公共知识 RAG 继续使用 `scripts/verify_rag.py` 的相应模式。具体本轮实测结果见 `.sandcastle/results/issue-7.md`。
